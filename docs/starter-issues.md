# Starter issues

Four issues were opened on 2026-10-01 as a way in for new contributors. The
labels `good first issue`, `help wanted`, `bug` and `enhancement` exist on the
repository, but the issues were opened without them; the maintainer adds them
by hand (each issue → *Labels* in the right-hand column):

| Issue | Labels |
|---|---|
| [#1 The cleaning sheet shows the previous take's term count](https://github.com/michaelhejazi/spoken/issues/1) | `bug`, `good first issue` |
| [#2 Verify recording on iPhone end to end](https://github.com/michaelhejazi/spoken/issues/2) | `help wanted` |
| [#3 A second provider behind the Transcriber seam](https://github.com/michaelhejazi/spoken/issues/3) | `enhancement`, `help wanted` |
| [#4 Report how haptics and the warning tone behave on your phone](https://github.com/michaelhejazi/spoken/issues/4) | `help wanted`, `good first issue` |

The README's *Contributing* section links to the `good first issue` and
`help wanted` label pages, which list these once they are labelled.

Each issue says what done looks like. A new starter issue should do the same:
bounded, real, and one that someone new to the code can finish.
